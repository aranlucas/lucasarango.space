# React UI and streaming

Sources: [Chatbot](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot), [Transport](https://ai-sdk.dev/docs/ai-sdk-ui/transport), [Streaming data](https://ai-sdk.dev/docs/ai-sdk-ui/streaming-data), and [Message persistence](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot-message-persistence). Verify signatures against the installed `ai` and `@ai-sdk/react` packages.

## Message and transport boundaries

- Keep client conversation state as typed `UIMessage` values and render their `parts`. Convert to model messages on the server with `convertToModelMessages`, awaiting it when required by the installed version.
- Validate submitted messages with `validateUIMessages` or `safeValidateUIMessages`, including tools and schemas for persisted custom data or metadata. Schema validation checks shape; it does not prove client-submitted assistant messages or tool results were generated by your server.
- Read the current `useChat` and transport APIs before implementing request customization. Keep input state in the application; do not copy old hook options or helpers from another major.
- For SDK 7, compose `toUIMessageStream({ stream: result.stream, ... })` with `createUIMessageStreamResponse`. Use `createUIMessageStream` when emitting application data alongside model output. Preserve IDs and original messages when implementing persistence or assistant-message continuation.
- Propagate cancellation to the agent/model request. Handle stream errors through the appropriate callbacks; an outer `try/catch` alone does not catch every error emitted after streaming begins. Clean up application timers and event listeners on completion, errors, and cancellation.

## Typed tools and custom data

`InferAgentUIMessage<typeof agent>` is useful when the UI only needs the agent's inferred tool parts. In the installed SDK 7 definition, its custom data generic is `never`. For a UI that also receives custom data, use an explicit message type such as:

```ts
import type { InferUITools, UIMessage } from "ai";
import type { askTools } from "@/lib/ask-tools";

type AskData = {
  "waiting-status": { phase: "waiting" | "still-waiting"; message: string };
};

type AskMessage = UIMessage<unknown, AskData, InferUITools<typeof askTools>>;
```

This mirrors this project's `src/lib/ask-types.ts`. Use type-only imports so client code does not import server tool implementations at runtime. Recheck the inference helper's generics before changing this pattern in a future release.

## Transient versus persisted data

A data chunk with `transient: true` reaches `onData` but is not added to `message.parts`. The client updates application state explicitly, such as `setWaitingStatus(part.data)`.

SDK reconciliation by matching data type and ID applies to persisted data parts. A repeated ID on transient chunks does not perform message-state replacement. Describe the application's state update accurately in comments and avoid persisting temporary status as conversation content.

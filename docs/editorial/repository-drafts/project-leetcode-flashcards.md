Some of my repositories are interview-learning tools and some are old projects I returned to modernize. `leetcode-flashcards` belongs in that history: it was created in 2022, well before the December 2025 start of my agentic coding chapter.

The goal is to preserve useful study material while making the application understandable enough to continue working on.

The [repository](https://github.com/aranlucas/leetcode-flashcards) includes learning material organized by topic, a problem browser, and pages for individual problems. The learning route loads Markdown content and renders it through the application's component layer.

Its root README still describes the starter template, so it is a poor guide to the project's actual content. Looking at the routes and topic files gives a clearer picture: this is a study application with a substantial reference collection.

I would not infer a spaced-repetition scheduler simply from the repository's name. The confirmed context is interview learning and returning to older software.

The repository preserves an interface around interview material that can be revisited and modernized. A complete modernization account still needs one concrete before-and-after change and the role an agent played in it.

That distinction is useful to document: recovering context about an old project is itself work, and the README may lag behind what the application contains.

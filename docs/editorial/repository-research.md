## Editorial approach

The opening often describes the problem implied by the product rather than a confirmed personal origin story. The account of the work draws on repository evidence. The outcome distinguishes implemented capability, documented historical verification, and Lucas's reported real use. Drafts retain visible gaps where a personal event or outcome is missing. Do not publish an invented time saving, usage metric, exam outcome, trading result, or story of an agent's involvement.

Existing technical drafts retain their commit-linked implementation discussion, except Agents, which was rewritten for its current Go/SQLite/Railway architecture. Their detailed historical claims were not all independently re-audited in this pass. New articles cite current repository documentation or inspected source; links to `main` are live references and may evolve.

- **Agents:** older local draft described D1/R2 and private visibility. Current repository is public and documents SQLite on one Railway replica. The post now reflects that state.

- **Janella Cookbook:** root README and newer implementation notes disagree on model/embedding provider details. The post describes the intake behavior and attributes historical local QA to the notes without presenting those checks as newly run.
- **Set & Signal:** product documentation and current README differ on storage; plugin documentation also retains an older source name. The post avoids choosing an unsupported end-to-end storage account. Clarify provenance and Lucas's contributions before publication.
- **resume-carlos:** Lucas confirms workflow membership; source inspected has the old TeX document, with no JSON Resume input or reusable-renderer dependency. Keep the migration question open.
- **Raleigh:** trip is upcoming as of this review. No completed-trip or exam outcome is claimed.
- **Legacy projects:** recent maintenance commits are evidence of specific upkeep, not proof that an old application or hardware setup has been restored end to end.

## Reusable interview for the next post

Ask for one concrete episode, not an exhaustive project history:

1. What was happening when you decided to build or revisit this?
2. What did you ask the agent to do, and which agent/model was it?
3. What did you have to correct or decide yourself?
4. What happened when you used it? A limitation or abandoned experiment is a valid result.

Keep stable post filenames when improving titles. New and existing drafts stay `draft: true` until their personal claims and current behavior are ready for publication. The three pre-existing published posts retain their original publication metadata.

## Why 001 was shipped

It is the highest-leverage plan that is a substantial correctness fix on the
agent/service side, and the repo's own tests can fully verify it with mock
models. Every visitor is exposed: free providers are slow, and the repo's
research (`docs/research/freellmapi-ai-sdk-retries-2026-10-12.md`) shows a turn
can outlive the route's 60 s `maxDuration`, which cuts the stream with no error.
The audit also showed that the obvious fix (the SDK's `timeout`) alone is not
enough: a timeout reaches the browser as an `abort` chunk, which the popup
treats like the reader's Stop, so it would still show no error and no retry.
002 is a real abuse risk but depends on a measured cap; 003 is a direction
spike; 004 is platform configuration rather than code.

## Dependency notes

- 004 depends on 002: a per-request rate limit means little while a single
  request can carry an unbounded history.
- 001 and 002 both touch the chat route's tests but not the same functions;
  either order works.

## Findings considered and rejected

- Unauthenticated `POST /api/revalidate`: documented intended behavior (README,
  `docs/reliability-audit.md`) — it only marks public résumé data stale.
- Fallback when the résumé API is down (prompt build throws): rejected by
  `docs/reliability-audit.md` — no fallback with invented facts.
- `pnpm audit` high/moderate/low advisories (body-parser, minimatch, deepmerge):
  all come through the `shadcn` CLI, which the app uses only for its build-time
  `shadcn/tailwind.css` import; not reachable at runtime. Dependency bumps were
  out of scope for this run.
- `shadcn` listed in both `dependencies` and `devDependencies`: harmless
  manifest duplication; not worth a plan on its own.
- Forged assistant tool outputs in client history: impact is limited to the
  sender's own stateless conversation; the size side of this is covered by 002.
- Two jsdom tests timed out once on the first local run (151 s under memory
  pressure) and passed on the next two runs: environmental, not a test defect.
